# 入口与业务限流

当前使用单 Nginx 入口和现有 Redis，不新增业务表或中间件。本文阈值用于开发联调，未经过生产容量压测。

## 请求处理顺序

`浏览器 → Nginx IP/入口总量限制 → Go 鉴权 → Redis 用户令牌桶 → 参数绑定和业务用例 → 原有幂等、用户互斥锁与 MySQL 事务`

`me` 复用原有身份检查，身份检查成功后再限流。内部结算、消息消费、退出接口不套用用户令牌桶。重复操作请求也消耗请求额度；429 不进入业务用例，稍后用相同 operation_id 重试。

## 入口规则

配置文件为 `deploy/local/nginx/default.conf`。所有规则在 server 层统一声明，通过 map 空键排除不适用路径，避免 location 覆盖继承导致总量限制失效。

| 范围 | 速率 | burst |
|---|---:|---:|
| 全部 API，同 IP | 30/s | 60 |
| 全部 API，整个入口 | 100/s | 50 |
| 注册和登录，同 IP 共享 | 2/s | 5 |
| 注册和登录，整个入口共享 | 5/s | 10 |
| SSE 新建连接，同 IP | 1/s | 5 |

SSE 另限制同 IP 最多 20 条活动连接。所有匹配的规则同时生效，burst 使用 nodelay：短时突发直接放行，额度耗尽后立即拒绝。静态文件不占 API 额度。

入口 429 返回 JSON `{"error":"RATE_LIMITED"}`、`Retry-After: 5`，这个等待时间是保守建议，不是配额预留。后端自己的 429 和 Retry-After 保持原样。SSE 继续关闭代理缓冲，读取超时为 60 秒，后端每 15 秒发送心跳。

## 用户令牌桶与配置

键格式：`rl:<APP_ENV>:<service>:<group>:<verified_user_id>`。同服务的所有实例共享额度；轮换 Token、切换会话和切换同组接口不能获得新桶。单抽、十连、三十连请求均扣一个令牌。

| 环境变量前缀 | 接口分组 | 默认 RATE | 默认 CAPACITY | Redis 故障 |
|---|---|---:|---:|---|
| RATE_LIMIT_ACTIVITY_QUERY | records/:kind | 10 | 30 | 放行 |
| RATE_LIMIT_ACTIVITY_JOIN | join | 5 | 10 | 503 |
| RATE_LIMIT_ACTIVITY_OPERATION | draw、purchase、stage、宝箱、选款、下一轮、预览与确认/放弃 | 2 | 4 | 503 |
| RATE_LIMIT_RANKING_BOARD | board | 2 | 5 | 放行 |
| RATE_LIMIT_IDENTITY_ME | me | 5 | 10 | 放行 |
| RATE_LIMIT_NOTIFICATION_STREAM | stream 新建连接 | 0.2 | 3 | 503 |

在前缀后加 `_RATE`、`_CAPACITY` 即为完整环境变量；RATE 是每秒补充令牌数。Compose 已透传这些配置，可在项目根目录 `.env` 设置，重建相应服务容器使环境变量生效。非法值启动时报错。各实例必须使用一致配置。

Lua 使用 Redis TIME，一次原子完成读取、补充、判断、扣减和 TTL 更新；拒绝不会推迟令牌恢复。TTL 为填满桶所需时间的两倍，长期空闲自动释放键。规则调整不删除已有键；现有令牌被新容量截断，后续按新速率恢复。

限流使用独立 Redis 连接池，操作预算 100ms，禁用网络自动重试；脚本缓存不存在时由 go-redis Script 处理加载。超限返回 429，Retry-After 按预计等待时间向上取整到秒；依赖错误与超限分开处理。查询放行只表示限流器故障不主动阻断，鉴权、MySQL 等依赖仍可能失败。

## 注册、登录和并发保护

- 注册格式检查通过后，按规范化 IP 原子检查计数。前三次有效尝试增加计数并从本次起续期 60 秒，第四次及后续拒绝不计数、不续期。重复账号也计数。
- `REGISTER_IP_WHITELIST` 是逗号分隔的 IP/CIDR，支持 IPv4/IPv6，默认为空。仅绕过注册计数，不绕过 Nginx、登录失败限制或鉴权。
- 登录失败按账号记录，实际失败时续期 15 分钟，成功清零。第五次失败仍返回凭据错误，后续准入检查返回 LOGIN_LIMITED 与剩余等待时间。已通过检查的并发在途请求仍可能记录实际失败，计数不是密码验证互斥锁。
- 保留已有 identity 计数键，避免升级清零正在生效的限制。计数依赖故障返回 503；格式错误在计数前拒绝。
- 保留每实例 4 个密码计算槽位，满载快速返回 503 PASSWORD_CAPACITY。
- 保留活动用户 Redis 互斥锁和 MySQL 幂等事务；通知默认每实例 10000 条、每会话 5 条连接保护，跨 8 个分片统一统计，可通过 notification 启动参数调整。这些限制不等同于请求速率；10000 是准入上限，不代表已通过万连接完整网络压测。参见 [分片广播实现与验收](notification-service分片广播实现与验收.md)。

## 代理信任与部署

Compose 的 Nginx 只连接专用 ingress 网络，四个服务同时连接 ingress 与依赖网络，仍不发布宿主机端口。服务仅信任 Nginx 的固定 IP `/32`；Nginx 覆盖外部提交的 X-Forwarded-For、X-Real-IP，并补齐通知服务代理头。

默认 `PROXY_SUBNET=172.29.240.0/24`、`PROXY_IP=172.29.240.10`。若与主机/VPN/其他 Docker 网络冲突，在 `.env` 同时调整为同一空闲子网内的值，再重建网络。当前入口直接接收客户端连接；如增加上游代理，必须另外核定可信地址和真实来源 IP 规则，不能直接信任任意请求头。

## 观察、验证和回退

开发环境默认强制限制。已有用户的环境先把 Nginx 的 limit_req_dry_run、limit_conn_dry_run 改为 on，通过 `nginx -t` 后 reload；业务服务设置 `RATE_LIMIT_MODE=observe` 并重建容器。观察模式仍执行令牌桶和记录结果，但不因新增令牌桶的超限或依赖错误拒绝请求；注册/登录原有业务计数始终执行。确认阈值后，Nginx 两项改回 off，服务设置 `RATE_LIMIT_MODE=enforce`。

Nginx access log 包含 request_limit、connection_limit、request_time、upstream_time。Go 记录分组超限、故障、单次限流耗时；每 100 次请求或发生拒绝/错误时输出累计 requests/rejected/errors 与平均耗时。指标仅按服务和固定分组聚合，不按用户展开；日志计数随进程重启归零。

前端保留 HTTP 状态、业务码、Retry-After；普通操作不自动重试 429，保留幂等标识；SSE 取服务器等待时间与指数退避的较大值，再加随机抖动。刷新遇到 429、503 或网络异常不清理会话、不跳转登录，明确 401 才判为认证失效。

PowerShell 验证命令（在项目根目录，使用 Go 1.25.1）：

```powershell
# 普通 Go 测试；未配置外部依赖的集成测试会明确 skip。
& 'D:\Program Files\GO\go1.25.1\bin\go.exe' test ./pkg/... ./services/identity-service/... ./services/activity-service/... ./services/ranking-service/... ./services/notification-service/...

# 使用单独的测试 Redis，切勿指向业务实例；用例只清理自己创建的键。
$env:RATE_LIMIT_TEST_REDIS_ADDR = '127.0.0.1:<测试端口>'
& 'D:\Program Files\GO\go1.25.1\bin\go.exe' test -count=1 ./pkg/ratelimit ./services/identity-service/internal/identity/infrastructure/redis

# 启动并自动移除隔离的 Nginx 容器，使用临时上游验证入口规则。
$env:RATE_LIMIT_TEST_NGINX = '1'
& 'D:\Program Files\GO\go1.25.1\bin\go.exe' test -count=1 -timeout 180s -v ./tests/entrylimit

# 前端源码测试与构建，不包含依赖独立业务栈的 .local/live.test.ts。
npm.cmd --prefix web/h5 test -- src
npm.cmd --prefix web/h5 run build
```

容量校准需覆盖三十连、页面并行查询、多个用户共享出口及 SSE 重连。上述功能验证不证明生产容量。回退时可先将新增令牌桶切到 observe、Nginx 切到 dry_run；业务幂等、互斥锁和注册/登录安全计数继续保留，不执行清库或批量删键。
