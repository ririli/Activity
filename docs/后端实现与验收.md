# 后端启动与验证

本轮新增四个 Go/Gin 服务，入口位于各服务 `cmd/server`。本页记录实际交付状态，原设计文档中的“待实施”状态不会自动代表已经通过验收。

## 本地启动

在仓库根目录的 PowerShell 中执行：

```powershell
& 'D:\Program Files\GO\go1.25.1\bin\go.exe' run ./scripts/devkeys
$env:INTERNAL_TOKEN = '<自行生成的至少32字节随机字符串>'
$env:ALLOWED_ORIGIN = 'http://localhost:8080'
docker compose -f compose.yaml -f compose.services.yaml up -d --build
```

`devkeys` 创建 `.local/keys` 中的独立 Access/Refresh Ed25519 密钥；文件已忽略，不应提交。Compose 自动初始化数据库仅适用于**新数据卷**。已运行旧版数据库时，需先备份、审核并单独执行 `003_ranking_projection.sql` 和应用用户授权脚本，不要删除原卷来强制重建。服务账号只获得各自逻辑库权限。

初始化一个明确时间范围的活动（显式写数据，不在服务启动中偷偷创建测试活动）：

```powershell
$env:MYSQL_DSN = 'core_app:dev-local-core@tcp(localhost:13306)/activity_core'
$env:EDITION_ID = '1'
$env:EDITION_START = '2026-11-01T00:00:00+08:00'
$env:EDITION_END = '2026-12-01T00:00:00+08:00'
$env:NODE_ID = '100'
& 'D:\Program Files\GO\go1.25.1\bin\go.exe' run ./services/activity-service/cmd/seed
```

每个进程的 NODE_ID 必须唯一。时钟回拨或单毫秒ID耗尽时停止生成。Compose 中为四个服务分别分配1～4；命令行种子进程使用100。HTTP 默认在8080端口经 Nginx 暴露，内部接口不经 Nginx 暴露。开发数据库口令仅供本机，生产配置必须替换口令、开启 HTTPS、设置 COOKIE_SECURE=true 并配置准确的 ALLOWED_ORIGIN。

## 接口契约

响应为直接 JSON；错误结构为 `{"error":"CODE"}`。所有身份及业务ID以十进制字符串传递。注册/登录使用 `account,password,nickname`。Access 通过 Bearer 传递，Refresh 只在 HttpOnly Cookie 中传递。refresh/logout 要求准确 Origin 和 `X-Activity-CSRF: 1`。

|方法与地址|用途/参数|
|---|---|
|POST /api/identity/v1/auth/register|注册并登录|
|POST /api/identity/v1/auth/login|登录|
|POST /api/identity/v1/auth/refresh|固定会话期限内轮换刷新|
|POST /api/identity/v1/auth/logout|撤销当前会话|
|GET /api/identity/v1/me|账号与会话资料|
|POST /api/activity/v1/join|初始化参与并读取余额、轮次和规则，edition_id|
|POST /api/activity/v1/draw|edition_id,operation_id,pool_code=DAY/NIGHT,count=1/10/30|
|POST /api/activity/v1/purchase|edition_id,operation_id,product_code=5/52/525/1580/gift/top-up；top-up还需petals|
|POST /api/activity/v1/stage|edition_id,stage=3/5/8/11/15/17|
|POST /api/activity/v1/chest-open|edition_id，恢复或打开当前箱子|
|POST /api/activity/v1/chest-confirm|edition_id,id=chest_id|
|POST /api/activity/v1/select|edition_id,id=grant_id,item_id|
|POST /api/activity/v1/next-round|edition_id,from_round_no|
|POST /api/activity/v1/preview|edition_id，生成或恢复固定预览|
|POST /api/activity/v1/preview-confirm|edition_id，按原结果兑现|
|POST /api/activity/v1/preview-abandon|edition_id，放弃|
|GET /api/activity/v1/records/:kind|edition_id,before；kind=draws/flowers/rewards/summary/chests/preview/purchases|
|POST /api/activity/v1/tasks/claim|明确返回 TASKS_NOT_OPEN|
|GET /api/ranking/v1/board|edition_id，Top20与本人|
|GET /api/notification/v1/barrage/stream|带Bearer的fetch读取SSE|

每页最多20条，before为上一页最后一个记录ID。逐抽与奖励事实不会因页面汇总而删除。普通抽奖同ID同参数24小时内恢复，改参数/过期拒绝；成功映射永久保留。Redis故障时已完成普通抽奖可以从MySQL恢复，新交易拒绝。COMMIT结果未知返回 OPERATION_RESULT_UNKNOWN，应沿用原ID重试。

## 实现边界与未完成项

- 榜单目前使用MySQL一致性快照查询，已实现乱序积分事实补齐、累计投影、最终快照和可靠排名奖励/回执；**Redis ZSET同步快路径、缓存任务、重建与代际切换未完成**。当前没有把Redis当作事实来源，但未达到设计的加速方案。
- 资料查询已实现单次HTTP批量SQL查询；**设计中的批量gRPC资料接口未实现**。
- 撤销通过每次MySQL会话/账号校验实现；**Redis撤销黑名单与BigCache负缓存尚未接入**。已经成功退出的会话不能因Redis丢失而恢复。
- 目录已有分层，抽奖演算位于领域层；**部分购买、阶段、宝箱和结算编排仍集中于核心MySQL事务适配器，尚未完成三个上下文的应用端口拆分**。目前不是设计最终要求的全部DDD分层。
- 逐抽事实目前逐行参数化写入同一事务；**按表批量INSERT优化、结算任务租约/游标和长期缺口自动巡检尚未完成**。截止冻结前会分页核对并补齐全部正式事实。
- **H5旧 `/api/v1` 接口、数值ID和localStorage Refresh协议尚未迁移**；本轮未覆盖用户已有前端改动。新API不能直接宣称已与现有H5联调通过。HTTPS端到端SSE、浏览器重连和播放去重亦需前端联调。
- 尚需压力测试、故障注入、密钥轮换配置、完整指标/告警和生产部署验收。没有实际流量数据，未给出容量承诺。

这些差距涉及独立的缓存一致性、通信契约、上下文拆分和验收工作；现有代码不能据此称为“全部设计已完成”或“可直接生产上线”。

## 自动验证

```powershell
& 'D:\Program Files\GO\go1.25.1\bin\go.exe' test ./pkg/... ./tests/e2e ./services/identity-service/... ./services/activity-service/... ./services/ranking-service/... ./services/notification-service/...
```

`tests/e2e` 默认跳过，需要显式设置 E2E_BASE_URL、E2E_MYSQL_DSN（测试专用核心库）与 E2E_EDITION_ID。它会注册测试账号，并直接修改测试账号的轮进度来验证满轮边界，不能连接生产环境。`compose.verify.yaml` 配合独立项目名 activity-verify 使用23306/26379/25673和28080端口，不复用 activity-local 的数据卷。

## 本机实际验证记录（2026-11-04）

- 四服务通过 Go 1.25.1 编译、全量已有/新增单元测试及 `go vet`。
- 四个 Linux 服务镜像构建成功，在独立 `activity-verify` Compose 项目中运行；未迁移、清空或删除原 `activity-local` 数据。
- `TestBusinessFlow` 在真实 MySQL 8.4 / Redis / RabbitMQ / Nginx 下通过，覆盖初始化、抽奖重放/冲突、阶段、购买限购、满轮停止与145花瓣退款、三次不放回宝箱、选款、新轮、预览恢复/兑现、Refresh与退出撤销，并核对逐抽/点亮/奖励事实数量。
- `TestProjectionAndSSE` 通过：注册后自动出现0分榜单记录，批量昵称查询正确，Bearer SSE收到ready并通过Nginx收到Redis广播。
- 将测试期次2提前截止后，核心期次与榜单结算均到达COMPLETED；12条排名奖励均DELIVERED。此为小样本闭环验证，不代表已完成全部并发、崩溃和故障恢复验收。
- 联调修复了ASCII奖励编码、MySQL JSON规范化对预览摘要的影响、秒级时间字段的JSON类型，以及Nginx上游容器重建后的DNS缓存问题。

未完成清单还包括注册IP白名单配置、全面故障注入、完整可观测性与自动化截止验收。当前结果证明了主业务链路可以运行，未完成项仍以本文清单为准。
